# Upstream provenance and changes

Source: https://github.com/Godlander/objmc
Snapshot: main, retrieved 2026-11-12. Source and shader SHA-256 hashes are recorded
in `vendor/upstream_manifest.json` in the development tree.

Encoder source is retained verbatim in `vendor/objmc_upstream.py`. The packaged
`encoder.py` contains only the encoding functions/classes, generated by
`tools/adapt_encoder.py`. Its changes are:

- Replace PIL Image and ImageOps with the RGBA8 adapter in `pixels.py`.
- Remove GUI, console/CLI setup and external dependencies.
- Replace process exit with a Python exception.
- Save encoded textures to their explicit destination, without changing cwd.
- Remove an invalid backslash escape in a progress message.
- Provide `convert()` with deterministic default options and automatic compression.

Bundled `shaders/include/objmc_main.glsl` has two changes:

- Accept marker alpha 78 **and** 79, matching uncompressed/compressed encoder
  output (the upstream main shader accepted only 78 despite testing for 79).
- Remove the row-vector multiplication by ModelViewMat in the hand branch. It
  cancels model-view rotation/scale; omitting it lets standard first-person display
  transforms affect held geometry. World/GUI branches remain upstream behavior.

The original MIT license and copyright are included in `LICENSE-objmc.txt`.
No sample assets from the upstream resource pack are redistributed.


## obj-cubed backend (Java 26.3)

Source: https://github.com/JagerMeistars/obj-cubed, release 26.3v4,
commit 1755b00bb5754fb30aed13abd51fa44c63cdf562.
`objcubed_26_3/assets/` contains the 22 upstream shader files without local
shader modifications. Blob hashes are in `vendor/objcubed_manifest.json`.
`LICENSE-objcubed.txt` preserves the upstream MIT notice.

`cubed_encoder.py` ports the subset of objcubed.js pixel encoding needed for
single-atlas mesh items and vertex animation: opaque marker, two header rows,
q16 GUI identity, explicit v3 hand/ground markers and repeated-last-vertex
triangle padding. Blender coordinates are already block-centre-relative, so
unlike Blockbench's floor-origin export, no additional Y -0.5 is baked.
No Blockbench runtime or Node installation is needed. Slot model variants and
a white-tint display-context item definition are written by exporter.py.
